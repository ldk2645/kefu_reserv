# PDD 视觉 AI 客服副驾驶 V0.1：一次性交付给 Codex 的需求包

**版本：2026-10-28 · 需求已合并，替代此前聊天里全部零散 Prompt/PRD。**

## 你只需要做三步

1. 把整个压缩包解压到一个新的项目文件夹（建议目录名 `pdd-visual-copilot`），保留文件结构。
2. 在 Codex 中打开这个文件夹，复制 `给CODEX_复制这一段.txt` 的全文作为**唯一初始指令**。不要粘贴之前的聊天记录或旧版 PRD。
3. 让 Codex 按 M0→M1→M2→M3→M4 实际写代码和测试；第一轮目标是跑通 M0–M3。M4 是增量开发，不要阻塞第一版。

## 为什么有这些文件

- `给CODEX_复制这一段.txt`：唯一需要发送到 Codex 对话框的启动消息，极短，其余用仓库文件读取。
- `AGENTS.md`：Codex 开发时必须遵守的长期约束与优先级。
- `docs/01_产品需求_PRD.md`：功能定义、UI、范围、工作流、验收。
- `docs/02_技术架构与接口.md`：模块设计、数据契约、版本/失效机制、关键技术选择。
- `docs/03_产品知识库与采集.md`：SKU、说明书、FAQ、官方视频链接的数据结构和采集逻辑。
- `docs/04_Prompt与双人格.md`：运营侧桌宠 + 客户侧专业话术，及防幻觉、提示注入规则。
- `docs/05_里程碑与测试.md`：实施顺序、测试列表、完成定义。
- `docs/06_部署隐私与运行.md`：Windows 操作指南、隐私、API Key、采集限制。
- `docs/07_统一决策记录.md`：解决此前迭代中可能产生的相互矛盾要求。
- `config/*`：可调整人格与风险配置示例。
- `samples/*`：格式模板、纯虚构演示数据，**绝不可当作真实产品事实**。

## 五个特别重要的设计决定

1. 说明书是产品事实主要来源；售后承诺需要另行核验公司 SOP / 平台规则。
2. 官方视频**只存 URL**；人工核实正确、确认为可向客户发送的链接，可直接进入待审核回复；不必上传视频文件。
3. V0.1 **不能自动点击 PDD 发送键**；只提供“人工审核并复制”，随后由人粘贴发送。
4. 操作员界面的“小鲸”可以活泼，给买家的回复必须独立、礼貌、克制。角色原创，不复制第三方原画。
5. 默认在本机 OCR、数据最小化；外部模型 API 需要主动配置，调用前可预览脱敏内容。

## 先准备哪些真实材料

建议先准备 10–20 款高频产品的真实名称/型号、官方说明书 PDF 或官方来源链接，以及少量人工核实的官方视频链接。**没有这些也能用 demo 运行软件**，但不能据虚构演示资料回答真实客户。

## 验证环境

目标 Windows 10/11；Codex 如果运行在 Linux/macOS，必须在报告中区分“已自动验证”和“待 Windows 实机验证”，不得假称完成了 Windows GUI/多屏/DPI 的真实环境测试。
