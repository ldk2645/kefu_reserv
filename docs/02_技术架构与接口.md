# 02｜技术架构、模块接口与工程约束

## A. 技术栈（建议，不硬编码包版本）

- Python 3.11，Windows 10/11，PySide6（GUI），mss（屏幕区域采集），Pillow（预览/图像处理）。
- RapidOCR（包名 `rapidocr`）+ `onnxruntime`：本地中文 OCR。当前官方快速用法 `from rapidocr import RapidOCR; result=RapidOCR()(image)`，可用 `result.txts`, `result.boxes`, `result.scores`；实现时适配已安装版本，别使用老包 `rapidocr_onnxruntime`。
- PyMuPDF/pypdf 解析 PDF；python-docx 解析 Word；文本 Markdown/TXT 可直接读取。扫描版 PDF 允许对页渲染图片后**本地** OCR。
- SQLite 存储商品元数据、审核状态、来源、视频链接；检索 V0.1 用文档分段 + jieba 或字符 n-gram + rapidfuzz/BM25 简单排序。不要直接假设 SQLite 默认 FTS5 能正确分词中文；可为预分词字段建索引，或者先只做内存检索。后期再考虑向量索引。
- `httpx` 调用用户配置的 OpenAI 兼容 `/chat/completions` API；pydantic 校验模型 JSON，PyYAML 配置，pytest 测试。
- `python-dotenv` 可用于加载 `.env`；`openpyxl` 仅在需要 Excel 导入的 P1 使用。

参考官方文档：
- RapidOCR：https://rapidai.github.io/RapidOCRDocs/main/quickstart/
- RapidOCR 安装：https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/install/
- PySide6：https://doc.qt.io/qtforpython-6/

## C. 输入到输出的数据流

```text
用户点击截图
  -> CaptureService.capture(region) -> 图片（内存）
  -> OCRService.recognize(image) -> OCRLine[] (text,bbox,score)
  -> ConversationEditor（操作员确认 latest_customer_message、sku、上下文）
  -> ContextFingerprint（确认文本 + SKU + 会话本地 ID 的哈希）
  -> ProductMatcher（已审核的 SKU/别名匹配；歧义拦截）
  -> RetrievalService（已审核说明书/FAQ/SOP，附源页码）
  -> VideoService（已批准的官方 URL + 精确 SKU/型号 + 意图）
  -> RiskEngine（确定性规则优先）
  -> DraftService（Mock / 在线 LLM，生成结构化 JSON）
  -> OutputValidator（引用/URL 由程序注入，不信模型虚构的引用）
  -> UI 展示草稿 + 来源 + 风险 + 视频
  -> UserReview（确认后） -> 剪贴板 -> 用户自行在 PDD 粘贴发送
```

## D. 数据契约

### OCRLine（返回顺序保守）
```json
{"text":"我的耳机连不上","bbox":[110,120,300,150],"confidence":0.93,"speaker":"unknown"}
```
上下文中 `speaker` 默认为 unknown，可根据用户手工指定。不要仅凭气泡在左/右就武断决定角色。OCRLine 可以显示在 UI、由人修正。会话对象只保留内存态，默认不落盘。

### ConfirmedContext（人工确认后才能用于模型）
```json
{
  "session_local_id":"volatile-1",
  "capture_id":"cap-0001",
  "confirmed_by_user":true,
  "latest_customer_message":"我的耳机连不上",
  "conversation_context":[{"speaker":"customer","text":"我的耳机连不上"}],
  "product_id":null,
  "sku":null,
  "context_fingerprint":"sha256-of-confirmed-fields"
}
```

### KnowledgeHit（由检索程序提供）
```json
{"source_id":"manual-001","source_type":"official_manual","verified_status":"approved",
 "product_id":"DEMO-A","section":"配对","page":3,"excerpt":"这是用于程序测试的虚构内容",
 "source_url":null,"score":0.85}
```
**严禁让模型生成虚构 source_id、页码、原文或官方认证状态。** 模型只能选择程序已提供的 ID 或不选。

### VideoSuggestion（来自本地库）
```json
{"video_id":"vid-001","product_id":"DEMO-A","intent":"pairing",
 "title":"已核实的官方配对教程（演示）","url":"https://example.com/demo",
 "verified_status":"pending","can_include_in_customer_reply":false}
```
注意：样例 URL 为占位，不能发送给真实客户；实际应用中只有 `approved` + 正确型号 + 官方来源确认时才 `can_include_in_customer_reply=true`。

### Draft
```json
{
  "intent":"how_to_use",
  "risk_level":"R1",
  "missing_information":["准确型号"],
  "customer_reply":"您好，麻烦您发一下耳机的具体型号，我核对后帮您确认配对步骤哈。",
  "operator_note":"型号不明，暂不提供型号专属步骤。",
  "used_knowledge_ids":[],
  "used_video_ids":[],
  "context_fingerprint":"sha256-of-confirmed-fields",
  "requires_human_review":true
}
```

`used_knowledge_ids`、`used_video_ids` 必须是本次程序召回提供的 ID 子集；程序对视频进行二次校验后附链接。不要直接使用 LLM 输出的任意 URL。要保证人工编辑后的回复仍需确认，允许手工移除视频链接。

## E. 会话版本与过期

- 触发识别产生 `capture_id`，对**用户确认过的聊天文本、SKU、会话 ID**计算 `context_fingerprint`；只因截图窗口时间变化但内容不变，不应误判过期。
- 一旦确认文本、型号、会话 ID 改变，旧 Draft `stale=true`，禁用无提示的“审核并复制”；需要重新生成或用户明确复核（优先重新生成）。
- 点击“新会话”清空缓存、引用、草稿和客户上下文，不自动保留上一位客户对话。
- 正在执行异步任务时若会话切换，迟到的 OCR/API 响应不可覆盖新会话。

## F. UI/并发/失败恢复

- OCR 与 API 用 QThread/worker（或等价机制）异步；主线程只更新 UI。
- OCR 空值、误分段、API 超时、响应不是 JSON、没有命中商品、离线/无 key 都有清楚提示；不要让 GUI 崩溃。
- 支持导入本地测试截图，降低 Windows 框选难调时的开发阻塞。
- 支持不同缩放/多屏：截图选区使用屏幕物理像素坐标；必要时处理 DPI scale，失败给重新框选入口。
- 避免无限重试/自动隐藏错误；限定 API 超时与重试次数。

## G. 网络/模型接口

环境变量：`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`、`AI_ENABLED=false`。使用 API 时给用户显示发送前预览/脱敏结果；无 Key 或未开启时使用 MockProvider（不是假装调用真实 AI）。远程只发送已确认必要文本与检索摘要，不发 OCR 图片或完整未经脱敏订单数据。

在 UI 中区分“演示回复”与“AI 回复”，不能让客服误把 demo 资料当官方说明。长期可考虑本地模型，但 V0.1 不必。
