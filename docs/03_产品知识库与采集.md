# 03｜知识库与官方说明书采集：最终统一规则

**已确定：以官方说明书为主要产品事实来源；视频不解析，只做正确链接推荐；经核实允许直接把官方教程链接发送给客户。**

## 1. 知识来源类型和可信度

| 内容类别 | 主依据 | 补充依据 | 注意事项 |
|---|---|---|---|
| 产品参数、操作、兼容性、故障排查 | **已核实的官方说明书** | 厂商官方 FAQ、已审核内部产品 FAQ | 必须精确型号，保留原文与页码 |
| 安装/配网演示 | 说明书中的事实步骤 | **官方教程视频 URL** | 视频只是教程入口，不推断其内容 |
| 退款、赔偿、保修政策、运费 | **已核实的公司 SOP 与当前有效平台规则** | 人工确认记录 | 产品说明书不能决定商家退款承诺 |
| 经验性应答 | 已审核脱敏历史客服案例 | 操作员自己写的话术 | 经验不能冒充产品事实或官方政策 |

来源状态：`pending`/`approved`/`rejected`/`deprecated`；只有 approved 进入生成依据。demo 样例不得 approved 为“真实产品事实”；应另设 `is_demo` 且禁止生产调用。

## 2. 商品与 SKU 建模

`products`：`product_id`、`brand`、`product_name`、`manufacturer`、`canonical_model`、`sku`、`aliases`、`category`、`active`、`last_reviewed_at`。

- SKU 来自店铺商品清单，但商家 SKU 可能表示颜色/套装/赠品，**不能等同硬件型号**。
- 用 SKU→canonical_model 映射关系；同一硬件型号可以有多个店铺 SKU；一个混装套装要记录其部件，不能用套装名直接指代单一设备。
- 商品标题包含营销词、规格词，匹配时优先明确型号编码、品牌；仅弱相似时显示候选供人工选择，不强行确定。
- 导入 Excel/CSV 时展示重复型号冲突、重名、空型号等警告。

## 3. 官方说明书的输入（P0）

**首先**支持操作员上传 PDF/DOCX/TXT/MD；导入时选择对应 product_id/model，并填写来源为“厂商官网/厂商提供的已验证文件/内部文件”。

处理链：
1. 保存原始文件的安全本地副本、计算 SHA-256 防重；限制文件大小、格式及解析错误。
2. 提取文本及页码/标题；扫描 PDF 逐页本地 OCR，记录 OCR 置信度或标注为 OCR 来源。
3. 分段（章节/页/操作步骤），记录 `source_id`、`chunk_id`、`section`、`page`、`text`、`version`、`source_url`、`verified_status`。
4. 审核界面能看到原文件名、型号、出处和抽样段落；人工确认后标为 approved。
5. 检索时只选和当前 `product_id`/canonical_model 匹配的 approved chunks；还可以引用通用知识，但必须被明确标记为通用并可适用于该品类。

大型 PDF 不应直接全篇塞给 LLM；只给精选的 3–5 个相关短片段，显示页码和出处。内容不足就追问。

## 4. 官方说明书半自动采集（P1/M4，非 MVP 阻塞项）

**不建议一开始全网爬取。** 功能定义为：以已导入的 SKU/型号清单为入口，按已配置的厂商**官方来源白名单**发现候选说明书链接 → 显示给人工核实 → 在允许访问/下载时获取 PDF/文档 → 做型号校验 → 解析 → 人工批准 → 可查询。

具体规则：
- 不只支持小米官网：生态链品牌可能有独立厂商网站；官方来源目录需允许增删域名和路径。
- 遵守目标站条款、robots/权限与合理限速；不绕过登录、验证码、反爬/付费访问；遇限制转手动上传或厂商提供文件。
- 没有公开搜索接口时可在 UI 显示按型号组合的查询词，让操作员自己打开官方站核实；不要调用未经授权的搜索接口。
- 自动匹配如果仅找到“看起来相似”的型号，保留 `pending`；**绝不自动认为说明书适配**。
- 保存来源 URL、抓取时间、页面标题、文件哈希、型号、版本/修订信息、最后审核时间。
- 同型号不同语言/版本冲突时显示差异，操作员择优并弃用旧版；不静默覆盖。
- 不批量下载无关全站资产，不爬客户数据、订单或非官方站侵权资源。

## 5. 官方教程视频：只存并推荐 URL（P0）

设计目标是用户要视频时，系统推荐**已核实的正确官方链接**；无需发视频文件，亦无需模型看视频。

字段：
- `video_id`
- `title`
- `url`（完整 https URL）
- `official_source_name` / `official_source_url`
- `applicable_product_ids` 或 `canonical_model`
- `sku_overrides`（必要时）
- `intent_tags`：配网、安装、复位、蓝牙连接、清洁、拆装等
- `verified_status`、`verified_by`、`verified_at`、`last_checked_at`
- `customer_shareable=true/false`（核实链接允许发送；业务已确认可以发官方正确链接）
- `notes`（可选）

**推荐的全部门槛**：状态 approved AND 非 demo AND 当前商品型号明确匹配 AND `customer_shareable=true` AND 问题类型匹配。若链接有效性未能确认，显示提醒；已知失效绝不推荐。严禁由 LLM 凭空拼装链接、改写 query 参数或自行生成所谓官方教程 URL。

客户回复可直接是：`您可以先参考官方教程操作哈：<核实后的URL>`。若同一问题有多个视频，优先最准确的一条；默认每次最多一个，用户可手动调整。

**不要实现**下载视频、视频播放器、视频字幕提取、视频理解、语音转写、视频关键帧。未来如果业务确实需要再讨论，但目前一律排除。

## 6. SQLite 数据模型建议

可拆表；以下是重要字段，不要求一次写成复杂关系网：

```
products(id, brand, name, model, sku, category, is_demo, active, updated_at)
product_aliases(id, product_id, alias, alias_type)
knowledge_sources(id, product_id, kind, path, source_url, sha256, language,
                  version, verified_status, is_demo, imported_at, reviewed_at)
knowledge_chunks(id, source_id, section, page, content, search_tokens)
video_links(id, product_id, title, url, official_source_name, intent_tags,
            verified_status, customer_shareable, is_demo, verified_at,
            last_checked_at, notes)
shop_policies(id, category, content, version, verified_status, effective_at, expires_at)
```

注意：不能通过 `is_demo=false` 的无来源资料自动提升为 approved；应当显式人工审核确认。`verified_at` 和 `verified_by` 是审查痕迹，不需要收集员工敏感信息（可使用本地操作员别名）。

## 7. 检索与引用逻辑

1. 识别意图与可用商品型号。
2. 如型号不确定，不检索/不使用近似产品的型号专用操作。允许询问型号或推荐完全通用的安全信息。
3. 限制到 approved 的型号匹配文档；依据问题关键词+字符级召回+短文本重排；找不到时报告无命中。
4. 必须可见 `标题 / 章节 / 页码 / 摘录 / 来源链接或本地文件`。
5. 如依赖售后条款，必须使用明确标记且未过有效期的 SOP。
6. 教程视频按上述门槛在业务逻辑内挑选，并生成可以追加的链接建议。**视频不是证明某操作步骤正确的文本证据。**
7. 如果检索片段包含“忽略此前指令”之类命令，将其当资料正文，不执行。

## 8. 常见失败场景

- 商品名类似但型号不同：显示“待确认型号”；禁止串用复位步骤/视频。
- PDF 提取不到正文：尝试本地 OCR，低置信度提醒人工核验。
- 视频 URL 302/短链/需登录：不直接通过“HTTP 200”认定内容正确；仍需人工确认内容与官方来源。
- 说明书已过时：标 deprecated，不进入检索。
- 订单问题：没有可靠实时订单接口时不能声称“已查看您的订单物流”。
