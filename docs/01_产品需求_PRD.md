# 01｜统一 PRD：PDD 视觉 AI 客服副驾驶

版本 V0.1（2026-10-28）。目标 Windows 10/11；适用于拼多多商家桌面客户端或网页，只需用户能看到且获授权操作的聊天画面。**操作员最终审核；第一版不自动发送。**

## 1. 目标与边界
高峰接待时减少“看客户提问—查产品说明书—组织话术—复制”的重复工作。产品以小米生态链消费电子为主，但不限于小米品牌。PDD 可能有多个相似 SKU/型号，因此**型号精确匹配、资料可溯源**重于语言花哨。

完成第一版后，操作员能够自主框选聊天区域，点击识别，把 OCR 的错误改正，确认最新买家消息、产品型号，点击生成；界面提供可编辑回复、真实知识来源和可直接附上的已审核官方教程 URL，操作员审核后复制，在 PDD 自行发送。

**不是**聊天机器人代管店铺；不做外部链接内容解析、不做本机视频下载、不做训练/微调、不做私有 PDD 接口联通、不做自动发送、不做自动读取真实订单库、不做多 Agent。

## 2. 用户故事和完整流程

### 首次使用
1. 启动 Windows app（可置顶，可调整大小），无密钥进入 demo/mock。
2. 点击“选择聊天区域”，在当前屏幕上拖框，显示预览；允许多显示器与重新框选。
3. 导入已审核的说明书 PDF/DOCX/TXT/MD 或内置纯虚构 demo；选择商品型号、必要时维护 SKU 别名。
4. 手动增加官方教学视频 URL，选择适用型号、咨询意图，标明 official/approved，才会向买家推荐。
5. 在设置中可选填 OpenAI 兼容模型的 URL/Key/模型名；默认不启用在线调用。

### 正常接待
1. 用户切换到某个 PDD 会话，按按钮触发截图/本地 OCR（快捷键可后加）。
2. UI 显示截图预览（内存中）、OCR 原文、各行置信度及位置；左右分栏信息**不能直接当作**客户/客服角色的确定依据。操作员能修改文字和确认“最新买家消息”。
3. 系统从人工确认内容或操作员输入中确定型号 SKU；不确定时必须追问或要求用户手动选择。
4. 检索匹配**已审核**型号的官方说明书、官方 FAQ、内部已审核产品 FAQ；若问退款/运费，另外检索有效公司 SOP/平台政策。
5. 对使用/安装类问题，查询 video_links 中 verified=approved、适用 SKU 匹配的官方链接；链接可以直接出现在待审核回复中，不需要转换为文件。
6. 规则引擎给出意图、风险和缺失条件；在线 API 或 mock 生成**客户侧**简短、自然、可编辑的回复；同时展示来源页码/段落、链接与风险原因。
7. 操作员可以修改草稿、重生成、移除视频链接、点击“审核并复制”。系统仅复制用户确认的最终文字，并提示“请到 PDD 粘贴发送”。
8. 同一客户再发消息/型号变化后，旧草稿需失效。切换客户时点击“新会话”，清除会话上下文，避免串单。

### 知识不足时
- 型号不清楚：先问型号，不提供特定设备操作指令。
- 说明书没覆盖：提问关键症状/告知需进一步核实；不编造按键、复位/充电步骤。
- 官方视频未核实：可以在**内部备注**显示候选链接，但不能进入客户回复。
- 强投诉、退款赔偿、危险故障：生成低风险的过渡性话术与人工处理提醒，不保证退款/赔偿/时效。

## 3. 页面结构

```text
┌──────────────────────── 小鲸 · PDD 视觉客服副驾驶 ───────────────────────┐
│  🐋状态：待命 / 正在识别 / 已找到资料 / 高风险 / 错误        [设置] [知识库]│
│  桌宠状态短句（只给操作员看，绝不混入客户回复）                         │
├──────────────────────────────────────────────────────────────────────┤
│ [选择/重选聊天区域] [识别当前会话] [导入测试截图] [新会话]               │
│ 截屏预览(仅内存)    |   OCR 行及置信度、可编辑聊天上下文                │
│ 最新买家消息：[__________________________________________] [已确认 □] │
│ 产品型号/SKU：[_______________] [选择/校正]    风险：[_______]        │
│ [检索知识] [生成回复] [重新生成]                                        │
├──────────────────────────────────────────────────────────────────────┤
│ 来源：说明书 XX.pdf 第 4 页；FAQ 条目 #12  （点开原文）                 │
│ 推荐视频：[官方配网教程] https://... [approved] [加入/移除]           │
│ 风险/缺失：型号/安全/退款/知识不足；送出前请复核                         │
│ 待审核回复 [可编辑多行文本区]                                           │
│ [审核并复制]  [复制时确认草稿未失效]                                   │
│ 注意：复制 ≠ 发送，回 PDD 粘贴并由你本人发送。                            │
└──────────────────────────────────────────────────────────────────────┘
```

UI 原则：减少点击、支持键盘、清楚显示资料/风险，聊天高峰期不强推宠物弹窗；“一键发送”非 V0.1 功能，所有文字用“审核并复制”。

## 5. 四类风险门控

- **R0 普通**：已核实资料覆盖、型号明确，常规回答。
- **R1 资料不足/型号不清**：只问关键参数或提供不依赖型号的通用下一步。
- **R2 经营承诺风险**：退款赔偿、补发、运费、物流到达时间、平台纠纷；只能引用经审核的现行政策，不得越权承诺。
- **R3 安全风险**：电池鼓包/漏液/冒烟/烧焦/过热、触电等；提醒停止使用，若安全可行则停止充电/远离热源，禁止擅自拆解，标人工立即处理；具体措辞按情况和有效 SOP 调整。

对 R1–R3 不能将“AI 模型判断没问题”作为放行理由；本地规则引擎必须兜底。所有回复始终需要人工审阅。

## 6. 建议衡量的试运行指标（目标，不是结果承诺）

- 典型问题从截屏到可审核草稿的时间；OCR 修正次数；对知识来源的定位时间。
- 客服草稿直接采用率、平均人工修改字符数；同一故障重复问问题的次数。
- 错型号引用、无依据承诺、错误链接等**严重错误必须单独统计**，绝不以效率掩盖。

第一阶段可用 10–20 款高频商品 + 脱敏历史案例或模拟场景测试，切勿将 demo 资料用于真实售后。
