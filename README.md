# 小鲸离线客服助手 · Windows MVP

已实现：用户主动框选 → 本地 OCR → 人工确认问题和型号 → 检索已审核资料 → 离线资料草稿 → 编辑 → 审核并复制。

**不自动发送、不接入 PDD 私有接口、不读取 Cookie。截图不写盘、不提交模型。** 内置演示资料全部虚构；已采集的真实资料独立保存，审核后才能用于真实客户。

## 安装与启动

新增独立的 **小米 KBS 有头采集器 V0.1**：人工登录与导航 → 检查实际 DOM/iframe → 本地结构化待审核 → 精确型号追加导入 → 小鲸离线使用。启动及验收说明见 [KBS_COLLECTOR.md](KBS_COLLECTOR.md)。四个限定分类已完成样本保存，真实资料均位于 Git 忽略的 `data/kbs_import/`，全部待人工核对；本轮不开放批采。

KBS 采集浏览器已按用户要求取消无痕模式，使用 `data/kbs_import/browser_profiles/` 下的独立持久配置，由浏览器保留登录 Cookie，关闭时不删除；程序不读取或导出认证数据。后续启动使用同一浏览器即可复用目录，站点仍可能要求重新登录。

已在 Windows 11、Python 3.13.15 x64 上实际运行。源码要求 Python 3.11+；本机没有 3.11，未单独验证该解释器。建议复现本次测试时使用 Python 3.13 x64 和依赖锁文件。

在 PowerShell 执行，无需激活虚拟环境或修改执行策略：

```powershell
git clone https://github.com/ldk2645/kefu_reserv.git
cd kefu_reserv
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe scripts/prepare_ocr.py
.\.venv\Scripts\python.exe -m app.main
```

首次克隆请完成上述安装步骤；已经安装过依赖并准备好 OCR 模型的工作区可直接执行最后一条命令。若使用 3.11，可将创建环境命令替换为 `py -3.11 -m venv .venv`，前提是系统已安装并注册该版本。

`requirements.txt` 是允许范围，`requirements-lock.txt` 是此次测试实际安装的精确版本。`prepare_ocr.py` 只复制 RapidOCR 安装包自带的三个 ONNX 模型到 `models/`，不发网络请求。不要给运行中的 OCR 传远程图片 URL。本版没有自动下载模型的运行时回退；模型缺失会显示明确提示并允许手工录入问题。

已安装好依赖的本机可双击项目根目录的 `start_xiaojing.cmd` 启动，不需要更改 PowerShell 执行策略。命令行支持 `start_xiaojing.cmd --first-product` 直接进入商品核对；窗口关闭后命令行窗口自动退出，启动失败会保留错误提示。该入口不安装依赖或联网下载模型。

也可运行 `./run.ps1`；本机执行策略实测会拦截该脚本，直接执行上面的 Python 命令或 CMD 入口即可，不必更改系统执行策略。

## 三分钟离线演示

1. 启动后看到黄色“虚构演示模式 / 离线检索与资料草稿”标记。
2. 点击“载入虚构演示截图”。此图片是程序绘制的测试素材，没有真实客户数据；真实本地 OCR 会返回原文、坐标和置信度。
3. 在左侧双击“这个演示摄像头怎么首次连接？”一行。修改错字，核对 `DEMO-CAM-A / SHOP-DEMO-01`，再勾选已确认问题与型号。左右气泡位置不决定角色。
4. 点击“生成 / 重新生成回复”。来源区显示 `demo_only`、原文、章节与本地副本。占位视频 `example.com` 不会进入草稿。
5. 修改草稿、勾选“我已审核当前回复、资料和链接”，点击“审核并复制”。演示标记不可删除，**不要把演示文本粘贴给真实客户**。
6. 修改问题、上下文或型号，旧稿失效；“新会话”清空上一客户的内存上下文与草稿。小屏可纵向滚动。

也可以“导入测试截图”选择 PNG/JPG/BMP，或者直接手工输入问题。OCR 失败不会阻止人工录入。

## 真实资料使用

在“知识库与视频”中操作：

- **商品与型号**：手工新增品牌、名称、硬件型号、店铺 SKU、逗号分隔的别名。同一硬件型号可以有多个 SKU；重复 SKU 被拦截。类似型号、歧义别名不自动匹配。混装套装请拆为部件录入。
- **说明书 / FAQ / SOP**：选择准确商品和类别、填写来源，再导入 PDF、DOCX、UTF-8 TXT/MD。默认 `pending`；查看段落、页码、哈希和本地原件，填写审核员别名、勾选核实后才能 `approved`。演示资料不能批准为真实事实。
- 原件保存于 `data/knowledge/`，按 SHA-256 去重，同型号/类别/版本不重复导入；更新须以新版本导入并人工弃用旧版。不静默覆盖原有审核结论。
- PDF 上限 20 MB / 100 页。扫描 PDF 或混合 PDF 中的无文字页会明确提示停止导入，请先用本地 OCR 转录并校对为 TXT。本版未实现逐页扫描 PDF OCR。DOCX 保留段落、表格；DOCX 没有可靠页码，因此按段落显示。
- SOP 需填 `YYYY-MM-DD` 生效与失效日期，过期条款不召回。退款、物流承诺与安全问题统一采用本地保守话术，同时显示检索到的有效 SOP 供人工处理。
- **官方视频 URL**：录入完整 HTTPS 地址、官方出处、适用型号、意图、审核员；人工打开核实后选择 `valid`、`approved` 并勾选可向客户分享。`unknown`、`broken`、未审核、演示或型号/意图不匹配的链接均不进入回复。可编辑并重新审核，也可撤回。

完成资料准备后，在“设置”取消“虚构演示模式”。离线草稿采用已批准资料的原文引用或保守追问，没有调用在线或本地大语言模型。每次最多添加一个合格视频，草稿中可移除；复制时再次检查当前审核状态。模式选择保存在本地 `data/preferences.json`，重启后沿用。

## 接入首个真实商品

```powershell
.\.venv\Scripts\python.exe -m app.main --first-product
```

也可在主窗口点击“接入首个真实商品”。窗口读取 `data/kbs_import/pilot_four_categories/` 的最新资料，只列出页面有明确型号证据的真实样本。全部资料仅在本地显示，不把品牌、型号、正文或 URL 发给任何模型。

1. 选择与实际在售商品一致的样本，填写真实品牌、店铺 SKU、核对依据和审核员别名。页面型号只读；不允许用相似型号代替，也不自动编造店铺 SKU。
2. 核对对应关系后点击“建立商品并追加为待审核”。原始采集文件不改写，人工补充的品牌/SKU 及依据另存 `kbs_product_bindings`，保留原始品牌、型号和来源。重复导入不会覆盖审核结论；已有 SKU 与型号不符时拒绝导入。
3. 阅读右侧“来源与原文”和“将用于检索的片段”，确认完整性、适用范围和对客使用条件后亲自批准。内部备注不进入检索片段；问题、答案、步骤及条件一起保存，标题本身不单独充当答案。
4. 输入典型问题并验证。只有实际引用该来源、错误 SKU 被拒绝、未经回复审核不能复制三项都通过，才允许切换到主窗口使用。长步骤不会截成半句；超过安全长度时提示进一步核对，完整原文仍可查看。
5. 在主窗口确认真实客户问题，检查引用，编辑并审核当前回复后复制。资料批准不会自动批准每条回复或视频，更不会自动发送。

流程进度保存在 `data/first_product/status.json`，只记录来源 ID、状态和验证统计，不保存客户问题或草稿。重新打开窗口可继续已保存的接入记录。两个样本均非在售商品时，先准备对应型号资料，不能把它们绑定到别的 SKU。

窗口会列出尚缺字段，仅在前置条件满足时开放下一步按钮。填写信息后还需要点击第 1 步保存；在对话中回复“已完成”不会代替本地保存和审核。已批准来源重新打开时保留审核状态，进入主窗口前重新进行离线验证。

只检查已有采集结构与接入数量，可运行：

```powershell
.\.venv\Scripts\python.exe -m app.services.first_product_preflight
```

此命令只读打开采集索引和应用数据库，报告写入 Git 忽略的 `data/first_product/preflight.json`，控制台仅输出统计。它检查型号证据、来源链接安全格式与结构化片段；不验证事实正确性或链接在线有效性，不创建商品、不导入或批准资料。

## 屏幕选区

“选择 / 重选聊天区域”仅打开透明选区框，不预先截取整屏。各 Windows 显示器分别提供选区，框选必须位于一块显示器内，支持负坐标和按显示器缩放换算。Esc 取消。选择后仅保存坐标；点击“识别当前选区”时才隐藏本窗口并采集选区。

不做持续监听或自动切会话。更换客户必须主动点击“新会话”；任何新识别都撤销确认，重新确认后才可生成或复制。仅因 `capture_id` 改变而确认内容完全不变，不判定旧稿内容失效。异步任务绑定会话、输入版本和请求序号，迟到结果不会覆盖新输入。

**尚未验证真实 PDD 抓图、混合 DPI 多显示器和系统截图权限。** 显示器布局改变后请重新框选；目前不支持跨屏矩形。

## 离线运行边界

2026-11-06 用户明确取消在线模型。本次决定覆盖原需求文档中有关可选在线 API 的要求：模型客户端、请求构造、发送预览以及地址/密钥/模型设置均已移除；旧 `.env` 或进程中的 `AI_*` 配置不会恢复在线功能。`.env` 仅保留可选的本地数据目录设置。

截图识别、检索、风险判断和草稿均在本机运行。缺少已审核资料时追问或转人工，不生成未经证实的产品事实。独立的 Selenium 采集器仍需访问获准网站；它与离线客服回复分开运行。

.\.venv\Scripts\python.exe -m pytest -q --junitxml=test-results/pytest.xml

`pytest` 默认 Qt offscreen，包含真实本地 OCR、服务测试和 Qt 操作测试。未准备 OCR 模型时两个真实 OCR 测试会明确 skip；本次已准备并执行，无跳过。基础测试历史见 [TEST_REPORT.md](TEST_REPORT.md)，当前离线与接入验收见 [OFFLINE_FIRST_PRODUCT_REPORT.md](OFFLINE_FIRST_PRODUCT_REPORT.md)。原生窗口演示渲染预览位于 `test-results/native-demo-window.png`，只包含本程序的虚构测试内容。

`offline_acceptance.py` 会打开可见 Windows 窗口，使用新建的隔离数据库与内存生成的虚构问题图片，运行真实本地 OCR。虚构夹具以非演示状态测试生产审核门槛，窗口仍显著标注“纯虚构”。它不读取日常数据目录、不抓桌面、不接触系统剪贴板；复制写入测试内存，Python socket 联网被拦截。最长 60 秒退出，结果和虚构窗口图分别保存至 `test-results/offline-acceptance.json`、`test-results/offline-acceptance-window.png`。这些检查不等同真实商品审核或 PDD 现场验收。

## 工程决策与边界

- 优先 M0–M3；M4 的 CSV/Excel 批导、白名单发现/下载说明书、联网检查视频及版本冲突比较尚未实现。
- SQLite 每次操作独立连接，文档解析、截图、OCR、检索与本地草稿生成通过 Qt 线程池处理。OCR 初始化仅一次、串行推理；后台任务运行时关闭窗口会提示等待，避免强制销毁线程。
- 中文使用字符二元词与英文/型号 token 召回，精确商品过滤优先；没有向量数据库。基于明确选择的商品 ID 绑定文档，不会把相似型号或另一个 SKU 的文件自动混用。同硬件多 SKU 暂须各自绑定导入。
- 扫描 PDF OCR 按 `docs/05` 允许的回退延期；遇无文字页明确拒绝，不把残缺正文当完整说明书。
- 本地草稿与人工编辑都做引用、URL、人格、经营承诺、常见功能/操作与数值检查；复制时重检，编辑会撤销审核。规则是保守启发式，**不能证明每句内容正确，也不能覆盖所有提示注入、敏感信息或隐含承诺**。不得替代操作员核对原文和风险。
- R2/R3 由确定性本地模板处理；没有经核实的经营授权时不承诺退款、赔偿或时效。输出仍有无依据引用和操作检查。
- `is_demo` 与 `approved` 严格分开，演示知识只可在演示模式显式检索；演示链接始终不可发送。客户草稿不拼接“小鲸”状态或内部备注。
- 手工视频可访问性记录是人工结论，不是自动 HTTP 检测。链接后续仍可能变化，操作员应复核。视频不下载、不开播放器、不解析字幕或内容。
- 真实采集资料仍需操作员核对；不能因保存成功就声称官方性和适用范围已验证。自动化用的非 demo 状态数据也是隔离临时目录中的**虚构测试夹具**，不导入日常数据库。

## 常见恢复方式

| 问题 | 处理 |
|---|---|
| 找不到 PySide6 / DLL 加载失败 | 使用 x64 Python 和项目 `.venv`；重新安装锁文件依赖 |
| 本地 OCR 模型缺失 | 运行 `scripts/prepare_ocr.py`，或暂时直接输入问题 |
| OCR 没识别文字 | 换清晰选区/图片；可直接人工录入 |
| 框选错位、屏幕布局变化 | 在同一显示器内重新框选；真实多屏/DPI 仍需现场验证 |
| 导入失败 | 检查 UTF-8 编码、格式、加密、文件大小；扫描 PDF 转录后人工校对 |
| 未召回资料 | 检查精确 SKU、审核状态、关键词与 SOP 有效期，不选择类似型号顶替 |
| 无法复制 | 检查问题确认、草稿版本、回复审核、演示标记和校验提示 |
| 首个商品验证不通过 | 检查真实 SKU、品牌/型号、资料审核状态和问题是否被原文覆盖；不批准错误资料来凑通过 |

实现时参考的官方接口资料：[RapidOCR 输出字段](https://rapidai.github.io/RapidOCRDocs/main/quickstart/)、[Qt 线程池](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThreadPool.html)。实际适配并测试的是锁文件中的 RapidOCR 3.10.0 与 PySide6 6.12.0。
