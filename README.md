# PDD 视觉 AI 客服副驾驶 · Windows MVP

已实现 M0–M3：用户主动框选 → 本地 OCR → 人工确认问题和型号 → 检索已审核资料 → 本地 Mock / 可选 API → 编辑 → 审核并复制。

**不自动发送、不接入 PDD 私有接口、不读取 Cookie。截图不写盘、不提交模型。** 内置商品与资料全部虚构；真实客户使用前需要导入并审核真实资料。

## 安装与启动

已在 Windows 11、Python 3.13.15 x64 上实际运行。源码要求 Python 3.11+；本机没有 3.11，未单独验证该解释器。建议复现本次测试时使用 Python 3.13 x64 和依赖锁文件。

在 PowerShell 执行，无需激活虚拟环境或修改执行策略：

```powershell
git clone https://github.com/ldk2645/kefu_reserv.git
cd kefu_reserv
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe scripts/prepare_ocr.py
.\.venv\Scripts\python.exe -m app.main
```

首次克隆请完成上述安装步骤；已经安装过依赖并准备好 OCR 模型的工作区可直接执行最后一条命令。若使用 3.11，可将创建环境命令替换为 `py -3.11 -m venv .venv`，前提是系统已安装并注册该版本。

`requirements.txt` 是允许范围，`requirements-lock.txt` 是此次测试实际安装的精确版本。`prepare_ocr.py` 只复制 RapidOCR 安装包自带的三个 ONNX 模型到 `models/`，不发网络请求。不要给运行中的 OCR 传远程图片 URL。本版没有自动下载模型的运行时回退；模型缺失会显示明确提示并允许手工录入问题。

也可运行 `./run.ps1`；本机执行策略实测会拦截该脚本，直接执行上面的 Python 命令已验证成功，不必更改系统执行策略。

## 三分钟离线演示

1. 启动后看到黄色“虚构演示模式 / 本地 Mock”标记。
2. 点击“载入虚构演示截图”。此图片是程序绘制的测试素材，没有真实客户数据；真实本地 OCR 会返回原文、坐标和置信度。
3. 在左侧双击“这个演示摄像头怎么首次连接？”一行。修改错字，核对 `DEMO-CAM-A / SHOP-DEMO-01`，再勾选已确认问题与型号。左右气泡位置不决定角色。
4. 点击“生成 / 重新生成回复”。来源区显示 `demo_only`、原文、章节与本地副本。占位视频 `example.com` 不会进入草稿。
5. 修改草稿、勾选“我已审核当前回复、资料和链接”，点击“审核并复制”。演示标记不可删除，**不要把演示文本粘贴给真实客户**。
6. 修改问题、上下文或型号，旧稿失效；“新会话”清空上一客户的内存上下文与草稿。小屏可纵向滚动。

也可以“导入测试截图”选择 PNG/JPG/BMP，或者直接手工输入问题。OCR 失败不会阻止人工录入。

## 真实资料使用

在“知识库与视频”中操作：

- **商品与型号**：手工新增品牌、名称、硬件型号、店铺 SKU、逗号分隔的别名。同一硬件型号可以有多个 SKU；重复 SKU 被拦截。类似型号、歧义别名不自动匹配。混装套装请拆为部件录入。
- **说明书 / FAQ / SOP**：选择准确商品和类别、填写来源，再导入 PDF、DOCX、UTF-8 TXT/MD。默认 `pending`；查看段落、页码、哈希和本地原件，填写审核员别名、勾选核实后才能 `approved`。演示资料不能批准为真实事实。
- 原件保存于 `data/knowledge/`，按 SHA-256 去重，同型号/类别/版本不重复导入；更新须以新版本导入并人工弃用旧版。不静默覆盖原有审核结论。
- PDF 上限 20 MB / 100 页。扫描 PDF 或混合 PDF 中的无文字页会明确提示停止导入，请先用本地 OCR 转录并校对为 TXT。本版未实现逐页扫描 PDF OCR。DOCX 保留段落、表格；DOCX 没有可靠页码，因此按段落显示。
- SOP 需填 `YYYY-MM-DD` 生效与失效日期，过期条款不召回。退款、物流承诺与安全问题统一采用本地保守话术，同时显示检索到的有效 SOP 供人工处理。
- **官方视频 URL**：录入完整 HTTPS 地址、官方出处、适用型号、意图、审核员；人工打开核实后选择 `valid`、`approved` 并勾选可向客户分享。`unknown`、`broken`、未审核、演示或型号/意图不匹配的链接均不进入回复。可编辑并重新审核，也可撤回。

完成资料准备后，在“设置”取消“虚构演示模式”。没有 API Key 仍可使用真实已批准资料的**本地保守草稿（Mock）**。Mock 采用原文引用或追问，不表示调用了 AI。每次最多添加一个合格视频，草稿中可移除；复制时再次检查当前审核状态。

## 屏幕选区

“选择 / 重选聊天区域”仅打开透明选区框，不预先截取整屏。各 Windows 显示器分别提供选区，框选必须位于一块显示器内，支持负坐标和按显示器缩放换算。Esc 取消。选择后仅保存坐标；点击“识别当前选区”时才隐藏本窗口并采集选区。

不做持续监听或自动切会话。更换客户必须主动点击“新会话”；任何新识别都撤销确认，重新确认后才可生成或复制。仅因 `capture_id` 改变而确认内容完全不变，不判定旧稿内容失效。异步任务绑定会话、输入版本和请求序号，迟到结果不会覆盖新输入。

**尚未验证真实 PDD 抓图、混合 DPI 多显示器和系统截图权限。** 显示器布局改变后请重新框选；目前不支持跨屏矩形。

## 可选模型 API

默认关闭。在设置中填服务商的 HTTPS 基础地址（通常以 `/v1` 结尾）、Key、模型名并主动启用。设置窗口的密钥只存在进程内。需要自行持久配置时：

```powershell
Copy-Item .env.example .env
# 用编辑器填写自己的 AI_BASE_URL、AI_API_KEY、AI_MODEL；需要在线时设置 AI_ENABLED=true
```

调用兼容 Chat Completions 的 `/chat/completions`，请求严格 JSON；不绑定具体模型或厂商。超时可设置 1–120 秒，默认 25 秒；单次请求，不自动重试、不跟随重定向。服务商如不支持 `response_format=json_object`，会回退本地草稿，需使用支持该接口的服务。

只有**真实资料明确覆盖的 R0 问题**调用外部模型；R1–R3 与演示资料均走本地保守模板。在线发送前弹出脱敏后的实际业务数据预览，人工确认才发；取消不发送。截图、全部 OCR、文件路径、会话 ID、密钥不放入模型输入。只发送必要问题、手工填写的相关上下文和最多五段资料。

手机号、长编号、带标签姓名/地址和邮箱做尽力脱敏；正则无法识别所有隐私，必须人工检查预览。关闭在线开关后不调用模型。错误不显示原始 HTTP 响应；客户原文、截图、Key 不写应用日志或聊天数据库。

本次没有真实 API Key：已用 `httpx.MockTransport` 检验请求契约、JSON、超时、重定向拒绝和回退；**未验证任何服务商的实际可用性、账单或模型质量**。

## 工程决策与边界

- 优先 M0–M3；M4 的 CSV/Excel 批导、白名单发现/下载说明书、联网检查视频及版本冲突比较尚未实现。
- SQLite 每次操作独立连接，文档解析、截图、OCR、检索与模型调用通过 Qt 线程池处理。OCR 初始化仅一次、串行推理；后台任务运行时关闭窗口会提示等待，避免强制销毁线程。
- 中文使用字符二元词与英文/型号 token 召回，精确商品过滤优先；没有向量数据库。基于明确选择的商品 ID 绑定文档，不会把相似型号或另一个 SKU 的文件自动混用。同硬件多 SKU 暂须各自绑定导入。
- 扫描 PDF OCR 按 `docs/05` 允许的回退延期；遇无文字页明确拒绝，不把残缺正文当完整说明书。
- API 和本地输出均做引用、URL、人格、经营承诺、常见功能/操作与数值检查；复制时重检，编辑会撤销审核。规则是保守启发式，**不能证明每句生成内容正确，也不能覆盖所有提示注入、敏感信息或隐含承诺**。不得替代操作员核对原文和风险。
- R2/R3 由确定性本地模板优先处理；模型只能提高风险。模型虚构引用、URL、明显无依据步骤或非法 JSON 时整次输出弃用。
- `is_demo` 与 `approved` 严格分开，演示知识只可在演示模式显式检索；演示链接始终不可发送。客户草稿不拼接“小鲸”状态或内部备注。
- 手工视频可访问性记录是人工结论，不是自动 HTTP 检测。链接后续仍可能变化，操作员应复核。视频不下载、不开播放器、不解析字幕或内容。
- 本机没有真实商品资料，因此不提供任何声称已官方验证的真实产品资料。自动化用的非 demo 状态数据也是隔离临时目录中的**虚构测试夹具**，不导入日常数据库。

## 常见恢复方式

| 问题 | 处理 |
|---|---|
| 找不到 PySide6 / DLL 加载失败 | 使用 x64 Python 和项目 `.venv`；重新安装锁文件依赖 |
| 本地 OCR 模型缺失 | 运行 `scripts/prepare_ocr.py`，或暂时直接输入问题 |
| OCR 没识别文字 | 换清晰选区/图片；可直接人工录入 |
| 框选错位、屏幕布局变化 | 在同一显示器内重新框选；真实多屏/DPI 仍需现场验证 |
| 导入失败 | 检查 UTF-8 编码、格式、加密、文件大小；扫描 PDF 转录后人工校对 |
| 未召回资料 | 检查精确 SKU、审核状态、关键词与 SOP 有效期，不选择类似型号顶替 |
| 无法复制 | 检查问题确认、草稿版本、回复审核、演示标记和校验提示 |
| 在线失败 | 状态明确显示本地回退，检查服务商 API 契约和 Key 后人工重试 |

实现时参考的官方接口资料：[RapidOCR 输出字段](https://rapidai.github.io/RapidOCRDocs/main/quickstart/)、[Qt 线程池](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThreadPool.html)。实际适配并测试的是锁文件中的 RapidOCR 3.10.0 与 PySide6 6.12.0。
